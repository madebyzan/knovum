# Knovum 0.4.0

This release adds Source Reading Mode — a docked reader beside the canvas that opens every kind of source you keep — unifies how a passage becomes a citation, restores your workspace when Knovum starts, and lets you set the canvas background. It is the largest release so far.

Source Reading Mode (`SpaceSourceReader`) opens as a resizable split pane next to the live canvas and reads what a Space holds: PDFs, Word `.docx`, presentations, spreadsheets and CSV, code, Markdown and notes, saved websites, audio and video transcripts, and images. Selecting a source node opens it; the reader switches between a reading pane and the node's information pane, walks your recent sources, renames inline, and accepts a drag onto the canvas. The right sidebar is now Conversation alone, so inspection and reading live in one place instead of three.

PDFs get the deepest surface. They open in an embedded viewer with a three-tab sidebar — lazy page thumbnails, the bookmark outline, and the excerpts you have linked — plus in-document find (`⌘F`), spread, rotation and fit controls, a rendered-Markdown text view, and a page-scoped OCR drawer. Highlights you capture from a source are painted straight back onto the page, and clicking one moves the viewer to it. You can annotate locally too: highlight, text and ink marks are saved atomically through Rust into the original file with ISO-compatible serialization. `Alt`-drag (or the Area tool) crops a rectangle out of a page into a Retina PNG image node that still knows the exact page and region it came from.

Word documents render natively with auto-fit width, in-document search and a structured-text toggle. Workbooks add a formula and cell inspector, live search and bottom worksheet tabs. Presentations get a full-width single-slide stage with a filmstrip, speaker notes and a continuous-scroll option. Saved websites offer an offline editorial Reader view and, when you want the real page, a live view in its own isolated native WebView with no access to Knovum, or a launch into your external browser. Markdown and notes render on a full-bleed editorial surface with heading jumps, text-size controls, syntax-highlighted code and one-click editing; code files get line numbers, wrapping and in-file search. Highlighting runs in its own worker with caching, and large spreadsheets and code files are virtualized, so opening a big source stays responsive.

One citation model now covers all of it. Selecting a passage in any reader resolves a locator bound to that revision of that source — a PDF page, a Word or website section with offsets, a media time range, code lines, or a document chunk — and a floating toolbar turns it into a sticky note, a structured Evidence object, an append to an existing note, or a quote into the conversation. Each capture is one undoable canvas edit and records both a `derives-from` relation and its provenance, so following a citation from the canvas returns the reader to the cited page, timestamp or section with the passage highlighted. Retrieval through connected MCP servers was rebuilt around the same idea: it fetches progressively instead of dumping whole documents, and commits what is worth keeping as structured knowledge. Pasting Markdown into an editor now brings the structure with it.

Relaunching Knovum can pick up where you left it. With **Restore previous workspace on startup** on — the default — the tab strip, active tab, sidebar and Inspector states, Inspector view, each Space's group scope, its active saved view, outline disclosures and the canvas camera all come back. Turn it off and startup opens cleanly at the Inbox. Unsaved drafts still do not survive a crash; normal navigation and quitting flush open documents and video projects as before.

The canvas can now be set to a dots or grid pattern, or nothing, and layered with one of five curated backdrops (Morning Mist, Summer Glow, Aurora Silk, Quiet Canopy, Dusk Tide), from Settings → Appearance or the canvas itself. Dots with no backdrop remains the default. Alongside this, automatic background visual understanding follows the visual route currently selected in Settings instead of staying pinned to the executor chosen when the job was queued; jobs already waiting, running or failed-retryable are released to the active route by this upgrade, while a request you made explicitly on a node keeps the model you picked.

On the dependency side this release pins `docx-preview` for native Word rendering and `shiki` for syntax highlighting, and enables Tauri's `unstable` feature for the multi-webview API the website reader needs. That second WebView is confined to the canvas-adjacent reader, accepts only `http`, `https`, `about` and Knovum's own preview scheme, and is granted no capability — no shipped capability declares a remote origin, so a page you read cannot reach a command.
