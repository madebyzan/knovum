# Knovum 0.0.3

This release moves creation onto the canvas and makes a derived picture answer for the input it
read.

Creating is no longer a dialog. Images, videos and documents are generated in place: a frame sized
to its output with a composer beneath it carrying references, prompt, aspect ratio or duration, and
executor. The add menu gains a Generate group, and Create from selection opens a generator beside
the selection with the selection already attached. Whether an action needs a selected resource is
now a property of the action, so the canvas request, the derivation engine and the Agent tool
schema all read the same number. A request may name the frame its output lands in instead of
placing that output beside its sources. Generation needs no input at all, and a document written
without references is drafted without retrieval or citations. The generator is a session draft: it
steps aside once its reserved output stands in the frame, and gives the frame back when a run ends
without publishing.

A derived picture can be compared with the exact input it read. Whether an output lays over its
source is a property of the transform, declared beside what it keeps: upscale, background and
object removal and object extraction compare, while depth, new views, and anything heard or watched
do not, and the backend alone decides. The comparison shows the input the derivation read, the
asset rendered with the edit recorded then, not the source as it looks today; an asset replaced
since leaves nothing honest to compare, so none is offered. It opens as the window rather than in a
titled dialog, at actual size from the centre, because fitted to the window an upscale and its
input look alike and there is nothing to see. A wipe divider spans the picture, the wheel zooms
around the pointer, and fit, actual size and the keyboard all reach the same view. The entry sits
icon-only in the node bar's access group, since comparing reads a node, as details and export do,
rather than making one.

The text selection bar now works. Its session ended on editor blur, and every control on the bar
and every menu it opens takes focus when pressed, so pressing Bold, a font size or a colour saved
and destroyed the editor and unmounted the bar before the click reached the control: the bar
vanished and no action applied. A session now lasts while the user is on its surface, which is the
node, its bar and the menus that bar opened, related through the aria-labelledby a menu or popover
carries to its trigger, and it ends on a press or a focus off that surface. Switching applications
no longer ends it either. On macOS, where WebKit never focuses a pressed button and moves focus to
the nearest focusable ancestor instead, the bar's focusable root is itself part of the editing
surface; a test drives the real bar, menu and editor with WebKit's focus behaviour and fails
without this.

A created note or text node appears from its creation instead of after a reload of the whole Space
projection, every node payload, scene and relation, which on a real Space took about two seconds.
Creation now answers with the nodes as stored, validated and revisioned, which is also its replay
receipt, and the session reads back only the structure and layout snapshot, skipping even that when
it already holds a snapshot at or past the creation's revision.

The empty canvas no longer promises a double-click it has never handled. It lists only what an
empty Space accepts, pasted clipboard content and dropped files, and the Korean and Traditional
Chinese hints that mistranslated dropping files are corrected. The empty state is drawn again with
new icons and layout, toolbar separators are quieter, and the sidebar outline renders only the
sections that have content. Shipped schemas are frozen: persisted data moves forward with the next
numbered migration, never by resetting a library.
