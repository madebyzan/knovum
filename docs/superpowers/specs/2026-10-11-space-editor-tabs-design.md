# Space 内文档与视频工作 tab

日期：2026-10-11。状态：待用户审阅；本文件不代表实现或验证已经完成。

## 目标与范围

在现有 Space 内，完整文档编辑和视频剪辑成为独立、可关闭、可返回的内容 tab。
用户可以在画布、多个文档和多个视频之间切换，保留草稿、编辑位置及各自的撤销历史。
Space 仍是资源与知识上下文的所有者。配音、有声书、图片工具继续使用现有交互。
已有 Note 的完整文档编辑复用同一文档能力；节点内短文本编辑保持原有方式。

基建只覆盖真实需要：tab 身份、激活与关闭、编辑会话生命周期、作用域明确的保存与退出协调。
不引入编辑器插件注册平台、通用文档模型、分屏、拖拽停靠、多窗口、预览 tab 或磁盘草稿库。
不引入兼容读取、迁移、静默保存失败、旧新状态双轨或为未来能力预留的空接口。

## 信息结构与交互

沿用已讨论的 Space 内方案：顶部 Space tab 保留；内容区有一条紧凑的工作 tab 栏。
仅存在画布时不展示额外 tab 栏；打开编辑内容后显示画布与该 Space 的内容 tab。
内容 tab 标题来自资源标题，配有类型标识、未保存状态和关闭按钮。
画布是每个 Space 的固定工作项，不能单独关闭。关闭最后一个编辑 tab 后返回画布。
资料库是导航目的地，不伪装为可编辑内容 tab；进入资料库暂时隐藏工作 tab 栏和编辑视图。

- 打开同一 Space、同一编辑种类、同一节点时激活已有 tab，不创建第二份草稿。
- 打开另一内容时新增并激活其 tab，不关闭当前编辑任务。
- 内容切换、进入资料库和切换 Space 保留编辑会话；回到 Space 时恢复上次活动工作项。
- 顶部 Space tab 的激活只负责选择 Space；回画布使用内容 tab 或明确的回画布命令。
- 关闭活动编辑 tab 后激活右侧相邻项，其次左侧项；关闭非活动项保持当前工作项。
- 文档编辑器的返回动作激活画布并保留 tab；结束编辑使用 tab 关闭动作。
- 关闭 tab 不删除节点，生成或导出完成不自动关闭 tab，也不抢占当前工作内容。
- Space 的 tab 被关闭时，关闭其全部编辑会话；重新打开 Space 从画布开始。
- 应用重启不恢复编辑 tab 或内存草稿。持续数据仍由现有节点与视频项目存储负责。

## 单一事实来源与所有权

| 所有者                           | 责任                                                            |
| -------------------------------- | --------------------------------------------------------------- |
| `features/spaces/workspace/`     | 有序工作项、当前活动项、打开/激活/关闭策略、Space 生命周期协调  |
| Spaces Pinia 会话状态            | 每个已打开 Space 的工作项与活动身份；跨视图状态保持             |
| `features/spaces/editor/`        | 文档草稿、Tiptap 实例及其原生历史、保存状态、位置与文档资源释放 |
| `features/spaces/video-editing/` | 视频项目草稿、编辑历史、保存状态与资源身份                      |
| 编辑器 presentation              | 当前视图的 DOM、焦点、播放器、时间线及可见性效果                |
| `shell/`                         | 通用桌面布局，消费能力可用性；不认识文档、视频业务类型          |
| `app/`、`foundation/`            | 继续负责应用导航、AppCommand 和退出协调；不持有编辑草稿         |

工作项使用明确的 `canvas | document | video` 判别联合；编辑项必须带 `spaceId`、`nodeId`。
不通过拼接字符串反解析身份。资源标题从所有者数据投影，不在 tab 状态里维护第二份标题。
资料库目的地与活动工作项分开表达：前者决定当前是否呈现工作区，后者保留编辑上下文。
原来的可写 `surface` 不与新活动项并存；需要该投影的调用方改为消费只读派生值。
所有旧的“打开编辑器就是替换编辑器”路径直接改为工作项操作，不保留旧分支兜底。

文档和视频分别拥有具体的会话集合；工作区只协调生命周期，不存放任意编辑器业务对象。
会话绑定稳定的 Space/节点身份；异步保存、代理准备与导出捕获该身份后执行。
编辑器不得在异步回调里重新取当前活动 Space 来决定写入目标。
保存必须继续通过现有节点内容/历史管线和预期内容校验；不得新建一套直接写数据库的入口。

## 会话生命周期与保存

区分三个操作，不能用一个含糊的 leave 方法同时承担：

1. 暂时切换：完成当前必须提交的输入事务，暂停可见性效果，保留编辑模型与历史。
2. 关闭会话：完成保存或显式放弃决定；成功后才移除工作项并释放所有者资源。
3. 提交持久内容：等待实际写入完成；写入失败保留草稿并显示错误，不等同于关闭。

文档继续自动保存。同 Space 切换 tab 保留编辑实例和光标/滚动位置；切换 Space 前等待
在途文档写入并提交待保存文本，失败则阻止该次 Space 切换。未激活 Space 的文档暂停
自动保存计时器，恢复时检查实际资源状态；没有变化的内容不产生写入。
Tiptap 历史由已有编辑实例持有，不自行序列化或重建 ProseMirror 的撤销记录。

视频 tab 暂时切换不触发保存/放弃对话框，项目草稿、历史、选中项、播放头和时间线缩放保留。
隐藏时暂停视频与音频；播放器 DOM 可释放并从会话位置恢复，后台不持续播放或刷新缩略图。
关闭脏视频会话提供保存、放弃、取消；保存失败保留 tab 和完整草稿。
关闭干净会话直接释放；关闭正在保存的会话等待结果，并重新判断是否还有更新后的修改。

编辑器命令仅由活动视图注册。隐藏会话不能接收保存、撤销、删除、播放或搜索快捷键。
文档来源预览和 transient overlays 在切换时关闭；文档历史与正文草稿不受影响。
画布继续保留镜头、选择与 Group scope；暂停手势和输入，不复制画布编辑模型。

会话参与者必须有明确的所有者范围。现有有序 content/layout/persistence 屏障继续负责
真实提交；其全局“切换就 finalize 所有编辑器”语义要改掉。
关闭单个 tab 只准备该会话；关闭 Space 准备该 Space 全部会话；应用退出准备全部会话。
其他节点工具继续遵守已有离开规则，不因新增 tab 绕过编辑租约或保存决策。
多会话关闭分两步：先按稳定顺序准备全部决定，再统一释放；任意取消或失败不移除 tab、
不清空草稿、不执行已准备的放弃。已经成功的持久写入无需人为回滚。

## 资源变更与后台任务

打开前验证节点归属和支持类型；异步准备完成后再次确认目标与请求身份。
删除、移动、归档等受控操作在移除所有者前协调涉及的会话；取消或失败阻止该操作。
刷新发现内容版本改变时，干净会话重新加载并重置其历史；有未保存修改的会话显式报告
冲突并阻止覆盖，不以自动合并、旧数据重解释或静默丢弃解决。
发现节点已不存在时关闭无主工作项并显示原因；若仍有未保存草稿，保留草稿并提供显式
放弃关闭，不能尝试写回不存在的节点。

视频渲染沿用 Tauri Channel 与 Task Center。启动前保存明确的项目快照；后续编辑不改变
在运行任务的输入。关闭干净 tab 不取消已启动渲染，取消入口由已有任务所有者负责。
输出发布到来源 Space；完成后提供显式查看结果动作，不跳转、不关闭其他 tab。
迟到的加载、保存和任务结果只更新原所有者，关闭后重新打开的会话使用不同生命周期身份。

## 依赖选择

要求：Vue 3 中的紧凑 tab、键盘/ARIA 行为、受控激活；不要求停靠、多窗口或新布局模型。
选择现有 `reka-ui` 的 Tabs 原语，Vue/Pinia 管理已明确的会话状态，Tiptap 持有文档编辑模型。
直接调用 vendor API；Knovum 代码只负责资源归属、关闭决策和异步生命周期策略。

- [Reka Tabs](https://reka-ui.com/docs/components/tabs)：已有直接依赖，提供受控激活与键盘行为，满足本次需求。
- [Dockview](https://github.com/mathuo/dockview) / npm `dockview-vue`：停靠布局不是本次需求，不引入第二套工作区布局模型。
- [Golden Layout](https://github.com/golden-layout/golden-layout) / npm `golden-layout`：多窗口布局管理不能替代 Knovum 的资源保存与会话策略，本次没有对应需求。

不新增 npm/crates 依赖，无新增 Tauri 权限、数据库表、窗口或进程。
候选比较不构成新依赖的安全/许可准入；现有锁文件与依赖政策继续有效。

## 验收与质量

- 同一文档重复打开不会重复；不同文档与视频可各自保留并正确激活。
- 文档/画布/视频往返以及 Space 往返保留各自状态，快捷键仅影响活动内容。
- 关闭脏视频的保存、放弃、取消与失败行为正确；批量关闭中途取消不会丢弃前面的草稿。
- Markdown 自动保存失败、保存中继续编辑、快速切换、资源删除/移动/刷新均有行为测试。
- 渲染中切换/关闭/重开 tab，迟到结果不会导航、写错 Space 或关闭新会话。
- 新 tab 控件支持键盘、明确焦点恢复、溢出滚动、长标题和窄窗口；选择器使用稳定标识。
- 检查后台媒体停止、会话关闭后销毁 Tiptap/监听器/计时器、重复打开关闭不累积注册。
- 更新 `docs/spaces.md`、`docs/architecture.md`、`docs/ui-system.md` 的对应权威契约。
- 使用 Composition API 与 `<script setup lang="ts">`；遵守文件 180 行、复杂度 10 与依赖方向。
- 聚焦行为测试通过后运行 `pnpm check:web`；已有无关改动引起的失败独立报告，不通过
  禁用规则、扩大豁免或修改无关代码消除。涉及退出协调的验证包括真实桌面关闭行为。
- 第一版完成条件是上述两个编辑器与生命周期契约通过验证；没有调用方的抽象不进入实现。
