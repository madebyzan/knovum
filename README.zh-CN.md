研究很少只围绕一种资料展开。一篇论文、一段录音、收藏的文章、尚未解决的问题，以及写到一半的草稿，
往往属于同一个项目。真正有价值的，是它们之间的联系。

Knovum 用 **Space（空间）** 承载这项工作：在一张无限画布上放置资料、组织想法、保留创作结果。
你可以建立论证、检查证据，再用选中的材料生成新内容，并保留结果回到输入资料的路径。

## 从一个问题到一份研究简报

以一个个人研究项目为例：你收集了几篇论文、文章和一段讲座录音，想理解这个主题，
再写出一份以后能够回查的简报。

### 1. 把上下文放到眼前

保存文章，导入论文与录音，写下自己的笔记。在画布上直观看到它们的关系，用分组、区段和保存的视图
组织项目的不同部分。网页保留原始 URL，提取的 PDF 文本保留页码位置；原始文件可以通过桌面应用打开。

### 2. 把推理过程表达清楚

给项目提出一个问题。用 **主张、证据、概念、实验和决策** 等结构化知识对象表达思考，
再建立 **支持**、**反驳** 等有明确含义的关系。知识检查会标记缺少支持的主张、已接受但存在反驳的主张，
以及来源已变更的证据，帮助你审阅论证中的缺口。生成一份草稿与接受一项主张，是不同的事情。

### 3. 用选中的材料继续创作

通过关键词或本地语义搜索找到相关段落。围绕来源提问，沿回答中的引用回到原文位置。
选中相关材料，再通过配置的模型或桌面 Agent 起草文档、生成可视化内容。

结果会成为空间中的另一个资源：可以编辑、搜索、建立关系，也可以作为下一步的输入。
本地转写能够把录音内容带入同一条研究流程。

### 4. 保留来路，复用过程

检查结果的派生记录，可以看到 **使用了哪些输入及其版本、执行了什么动作，以及实际运行的引擎或模型**。
来源后来发生变化，记录仍指向当时使用的版本；已有结果不会为了匹配新资料而被悄悄改写。

一组步骤完成后，可以将其已完成的派生链保存为 **可复用工作流**。下次为它绑定新资料，
再次运行，并把中间结果与最终产物一起保留在空间中。

**产物完成后，这些联系仍然有用。** 你可以回查一个想法背后的证据、检查资源的生成过程，
或者用新的输入重复已经实践过的步骤。

## 不止于研究简报

| 能力               | 可以做什么                                                                                                                        |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| **空间化工作区**   | 混合放置 Markdown、笔记、网页、文档、图片、音频、视频与代码；用分组、区段、标签和保存的视图组织内容。                             |
| **跨空间搜索**     | 在当前空间或多个空间中，通过关键词或语义检索资料。语义搜索使用本机计算的嵌入向量。                                                |
| **媒体与文档创作** | 本地转写、图片去背景、制作带字幕的视频，以及将支持的文档转换为 DOCX、PDF、HTML、PPTX 等格式。生成式媒体动作取决于所选模型的能力。 |
| **可携带的空间**   | 导出包含内容、托管资源、关系和派生历史的 `.knovumspace` 包；通过 JSON Canvas 交换画布。                                           |

支持格式、模型要求和转换限制见 [空间指南](docs/spaces.md)、[本地模型指南](docs/local-models.md)
及 [文档转换指南](docs/document-conversion.md)。

## 数据默认在本地，AI 由你选择

空间、托管文件、提取文本和搜索索引保存在你的电脑上。画布编辑与关键词搜索不需要生成式 AI 连接。
下载相应模型后，语义索引和转写在本机运行。

生成式动作可以选择模型连接或桌面 Agent。支持的连接包括 OpenAI、Anthropic、Google Gemini、
OpenAI 兼容端点和 Ollama。桌面 Agent 使用自己的认证与可用工具；Skills、插件和 MCP 连接可以扩展其能力。

选中的文本或媒体可能发送给你选择的执行端。哪些步骤在本地完成、哪些使用外部服务，取决于具体动作与连接。
详见 [AI 与本地模型行为](docs/local-models.md)。

## 开始使用

**Knovum 仍处于早期开发阶段。** 以下步骤用于从源码运行桌面应用。预发布数据格式可能变化，
更新开发版本前，请先导出重要空间。

| 平台    | 目标环境                                  |
| ------- | ----------------------------------------- |
| macOS   | macOS 14 及以上，Apple Silicon 与 Intel   |
| Windows | Windows 10 2004 / build 19041 及以上，x64 |

安装 **Node.js 22.13+**、**Corepack**、仓库指定的 **Rust 工具链**，以及
[安装指南](docs/installation.md) 中的原生构建依赖，包括 uv、CMake、Protobuf、LLVM/libclang
与 Tauri 要求的平台工具。pnpm 版本固定在 `package.json` 中。

```bash
git clone https://github.com/zandko/knovum.git
cd knovum
corepack enable
pnpm install --frozen-lockfile
pnpm desktop:dev
```

开发命令会准备 Agent 环境与原生组件，然后打开应用。首次构建需要下载依赖，耗时通常长于后续启动。

先从一个问题和两三份资料开始：创建空间，加入材料，写下你想弄清什么。
需要基于来源提问或生成结果时，再配置 AI 连接。本地模型会在请求相关能力时下载，提供进度与取消操作。
