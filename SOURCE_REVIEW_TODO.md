# 前端与 Rust 源码逐文件审查清单

范围：`src/` 的 TypeScript、Vue、CSS 与 `src-tauri/src/` 的 Rust、Typst 源码。测试、生成契约、静态图片/模型、翻译数据、工具环境声明（`*.d.ts`）、说明文档与构建产物不属于实现简化审查对象；它们仅在验证对应行为时使用。

目标：核对 Vue composable 与普通函数边界、重复/死代码、无意义封装、已安装库可直接承担的能力及错误处理；只做有明确收益且保持行为的整改。不新增依赖或兼容兜底。

判定边界：依赖组件实例/作用域的 composable 在 `<script setup>` 或其他组合式函数的同步执行阶段创建，事件回调只调用其返回的动作。Pinia 的 `useXStore()` 是官方支持在安装 Pinia 后由组件外的函数调用的 store 访问器，不按组件生命周期 hook 误判；参见 [Pinia 官方说明](https://pinia.vuejs.org/core-concepts/outside-component-usage.html)。

勾选规则：`[x]` 表示该文件已审查；若有整改，必须完成该项的针对性验证后勾选。`[ ]` 表示仍待审查。审查无改动也要逐项勾选。所有项目结束后统一执行 `pnpm check:web`、`pnpm check:rust` 和格式检查。

审查过程中同一工作区还有其它任务持续增删前端和 Rust 文件。清单已同步到当前文件树；新文件保持 `[ ]`，先前已经审查但被删除的文件从清单移除。后续须在并发改动稳定后逐项审查新增文件，并重新执行受影响的检查。
