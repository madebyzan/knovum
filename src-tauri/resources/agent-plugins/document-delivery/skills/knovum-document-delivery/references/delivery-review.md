# Deliverable review

Read after choosing the requested format and before reporting delivery.

Reports need a clear purpose, outcome-first structure, evidence locators and explicit limits. Proposals need a decision, scope, approach and success criteria grounded in available facts. Presentations need one point per slide, short supporting material and evidence references, not report-length prose pasted onto slides.

Reuse satisfactory existing documents when the request is export or conversion. Select the actual advertised export/render operation for the requested format. Built-in inference generation and external Agent generation have different executors; do not invoke unavailable inference Actions from an external Agent.

Inspect what the runtime actually generated: content completeness, correct format, readable structure, missing images/citations, and output receipt. Inspect visual layout only if a renderer/viewer is available; never claim a visual review based solely on a filename. Keep final artifacts separate from intermediates. A Markdown draft is not a PDF, DOCX or slide deck.

If delivery fails, report the actual failed operation and useful retained draft. Do not create an empty document or quietly switch the requested format.
