# Repository review
Read for source investigation or pull-request review.

Resolve the exact repository and ref. Read the changed code plus directly relevant callers/contracts. A valid finding explains the trigger, faulty behavior, impact and location; avoid speculative style comments. Distinguish an observed runtime failure from a static inference. Verify assumptions against dependencies or configuration when available.

For issue triage, check existing discussions and affected versions. Preserve links to evidence. Creating an issue, commenting, assigning, merging and pushing are separate writes: only perform those authorized by the user and admitted by the current tool policy. A proposed fix or unrun test is not a verified outcome.
